# Лабораторная работа №10

**Тема:** Сборщик модулей Webpack. Реактивное программирование на базе RxJS.  
**Проект:** CRUD-приложение "Сборник рецептов" (Express + JSON-файл + реактивный frontend).

## Цель работы

- подключить Webpack для сборки клиентской части;
- перейти с императивного подхода (`fetch` + ручные обработчики) на реактивный (RxJS);
- реализовать фильтрацию, сортировку, пагинацию и CRUD через потоки данных;
- сохранить backend из ЛР 8 (Express + REST + `db.json`).

## Краткая теория

### 1) Зачем Webpack

Webpack объединяет модули приложения в один или несколько бандлов.

- Точка входа (`entry`) определяет, с какого файла начинается сборка.
- Точка выхода (`output`) указывает, куда положить готовый бандл.
- Loader-ы преобразуют не-JS ресурсы (например CSS).
- Плагины (например `HtmlWebpackPlugin`) автоматизируют генерацию HTML и подключение бандла.

В этой работе frontend берется из `src/`, а результат сборки попадает в `public/`.

### 2) Что такое RxJS

RxJS — библиотека реактивного программирования на основе **Observable**.

Ключевые идеи:

- UI-события и HTTP-запросы представляются как потоки;
- потоки можно преобразовывать операторами (`map`, `switchMap`, `filter`, `startWith`);
- несколько потоков объединяются через `combineLatest`;
- подписка (`subscribe`) выполняет финальное действие (рендер, обновление состояния).

### 3) Почему `switchMap`

`switchMap` отменяет предыдущий внутренний запрос, если пришло новое событие.  
Это полезно при повторных обновлениях данных: приложение не "копит" устаревшие HTTP-ответы.

## Структура проекта

- `server.js` — запуск Express, раздача статики из `public`, маршрут `/`, подключение REST.
- `rest.js` — REST API `/items` (GET/POST/PUT/DELETE).
- `store.js` — слой работы с `db.json`.
- `db.json` — данные рецептов.
- `webpack.config.js` — конфигурация сборки.
- `src/index.html` — HTML-шаблон для Webpack.
- `src/style.css` — стили клиентской части.
- `src/app.js` — реактивная логика frontend на RxJS.
- `public/` — собранные файлы (`index.html`, `bundle.js`) и статические ресурсы (`images`).

## Пояснение кода

### `webpack.config.js`

- `entry: src/app.js` — стартовый файл клиентского приложения.
- `output: public/bundle.js` — итоговый JS-бандл.
- Правило `test: /\.css$/` + `style-loader`, `css-loader` — подключение CSS через импорт в JS.
- `HtmlWebpackPlugin` генерирует `public/index.html` по шаблону `src/index.html`.

### `server.js`

- Использует `PORT` из переменной окружения:  
  `const PORT = Number(process.env.PORT) || 3001;`
- Раздает статику: `app.use(express.static(PUBLIC_DIR))`.
- Корневой маршрут `/` отдает собранный `public/index.html`.
- API подключается через `app.use("/", restRouter)`.

### `src/app.js` (реактивная часть)

1. **Потоки интерфейса**
- `search$` — поток поиска (`input`).
- `sort$` — поток выбора сортировки (`change`).
- `refresh$` — поток кнопки обновления.
- `page$` — поток текущей страницы (BehaviorSubject).

2. **Загрузка данных**
- `items$` строится как `merge(refresh$, reloadItems$).pipe(startWith(null), switchMap(() => ajax.getJSON("/items")))`.
- `ajax.getJSON` возвращает Observable с массивом рецептов.

3. **Комбинация потоков**
- `combineLatest([items$, search$, sort$, page$])` дает актуальное состояние:
  - фильтрация;
  - сортировка;
  - расчет страниц;
  - выбор элементов для текущей страницы.

4. **Пагинация через браузер**
- Текущая страница читается из URL (`?page=...`).
- При смене страницы URL обновляется через `history.pushState`.
- `popstate` обрабатывает кнопки браузера "Назад/Вперёд".
- Дополнительно рендерятся номерные кнопки страниц.

5. **CRUD через RxJS**
- Создание/редактирование формы: `fromEvent(form, "submit")` + `switchMap(ajax(...))`.
- Удаление/редактирование из таблицы: `fromEvent(tableBody, "click")` + делегирование по `data-action`.
- После успешного CRUD вызывается `reloadItems$.next(null)` для реактивного обновления списка.

## Команды запуска

Установка зависимостей:

```bash
npm install
```

Сборка frontend:

```bash
npm run build
```

Запуск backend:

```bash
npm start
```

Приложение доступно по адресу:

- `http://localhost:3001`

## Проверка функциональности

- создание, редактирование и удаление рецепта;
- повторная загрузка данных кнопкой "Обновить с сервера".

В работе реализован переход от классического клиентского подхода к реактивному:

- backend из ЛР 8 сохранен без изменения архитектуры;
- frontend собирается через Webpack;
- пользовательские действия и HTTP-запросы объединены в потоковую модель RxJS;
- пагинация синхронизирована с браузерной навигацией, что улучшает UX.
